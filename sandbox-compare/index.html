The isolation ladder 🪜

Every sandbox occupies one of five tiers. Lower number = stronger isolation — each tier down shares more of the host with the untrusted code.

Tier 1 Hardware microVM — dedicated kernel per sandbox (Firecracker, Kata, Hypervisor.framework) ↓ Tier 2 User-space kernel interception — gVisor (syscall filtering, shared real kernel) ↓ Tier 3 Interpreter-level sandbox — language VM, code never sees the OS (Monty) ↓ Tier 4 Shared-kernel containers — Docker (container escape = host compromised) ↓ Tier 5 OS profiles only — Seatbelt / Landlock restrictions on an unsandboxed process

Tier 5 is what the built-in coding-agent sandboxes use — and per the Novee audit (below), it is the tier with the published escapes. Tier 1 is the only tier where a kernel exploit inside the sandbox does not touch the host.

Databricks Sandbox: isolation + governance 🟠

Two things nobody else combines

1. Downscoped UC credentials. Agents in the sandbox don't carry your token — they get dynamically-issued, task-scoped Unity Catalog credentials. Novee's finding was that credentials escape every architecture; Databricks' answer is to hand out less credential in the first place, not hide it better.

2. Governance inheritance. Code inside the sandbox queries data through Unity Catalog: row/column permissions, lineage and audit apply automatically. "What data did the agent touch" has a built-in answer — other platforms require you to build that audit layer yourself.

Plus Lakebase instant branching: agent writes go to a zero-copy DB branch, validated, then merged — database-level isolation matching the compute-level isolation.

Announced at DAIS 2026 as part of the Agent Bricks platform (alongside Agent Bricks memory, MCP support, and the Unity AI Gateway for runtime spend/policy control). Trade-off: it lives inside the Databricks ecosystem — the isolation is excellent but the blast radius of the option is your lakehouse estate, not the open internet.

Four design philosophies 🧭

The isolation tier is downstream of a philosophy choice — and the philosophy is what actually predicts the CVEs:

1. Start open, then restrict 🔓

Codex · Gemini CLI · Claude Code

Full environment first, then whittle down — network rules, filesystem rules, syscall filters. Cursor's sandboxing writeup documents how painful this is across platforms. Every vendor in this camp has a published 2026 escape.

2. Hardware isolation by default 🧱

E2B · Docker Sandboxes · AgentCore · Databricks Sandbox

Don't argue about kernels — give each sandbox its own. Strongest containment; the remaining risk migrates to credentials and data access, not the runtime.

3. Deny-by-default interpreter 🐍

Monty · Strands Box (Python layer)

Code literally cannot see the OS. Capabilities are functions you wrote, audited, and granted. Trade-off: a strict Python subset, no third-party packages. Philosophically closest to "firewall that blocks everything, then allowlists".

4. Governance-native 🏛️

Databricks Sandbox (+ Unity AI Gateway)

Isolation is table stakes; the differentiator is that data-plane permissions are dynamic and inherited. Built for enterprises whose #1 question is "what data could the agent reach, and who saw it."

The Novee lesson 🚨

October 2026 agent-sandbox audit (disclosed with Anthropic, Google, OpenAI)

  • Claude Code: 2 CVEs (CVE-2026-54316, CVE-2026-45786)
  • Gemini CLI: CVSS 10 chain — one public issue → credential compromise → push to main on a project with ~2M monthly installs
  • Codex: 2 independent sandbox-escape paths
  • The headline: "Credentials escaped in every architecture, including from a Codex sandbox with TCP, UDP and DNS fully disabled."

Conclusion: the isolation tier protects the host from the code. It does nothing for the secret the code legitimately needs. 2026's lesson: isolation is table stakes — credential architecture is the real differentiator (stand-in values, gateway injection, downscoped tokens).

The 2027 standard answer 🧩

The strongest stack combines all three lessons: microVM hard isolation (E2B / Databricks / AgentCore) + downscoped or injected credentials (UC downscoping / gateway stand-ins) + deny-by-default interpreter for generated code (Monty). Any one alone leaves a published 2026 gap.
